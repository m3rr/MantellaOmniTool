debug_config_dump.py

Purpose: Utility script that dumps the current configuration and runtime state to a JSON file for debugging and support purposes.

  • Imports json, os, logging, and internal utils.logger.
  • Defines CONFIG_DUMP_PATH defaulting to h4_omni_debug_dump.json in the application root.
  • Function collect_runtime_state() gathers:
    • Active settings from omni_settings.json.
    • Current process ID and thread count.
    • Loaded modules list via sys.modules.
    • Recent log entries (last 500 lines) by reading h4_omni_debug.log.
    • Network port usage via psutil.net_connections().
    • GPU information via torch.cuda if available.
    • Environment variables relevant to the tool.
    • Timestamp of dump creation.
  • Function write_dump() serialises the state to JSON with indent=2 and writes atomically using a temporary file.
  • CLI entry point parses optional --output argument to override the dump path.
  • Logs success or failure to h4_omni_debug.log with INFO or ERROR level.
  • Returns exit code 0 on success, 1 on failure.
  • Important notes:
    • Sensitive fields (API keys) are redacted before writing.
    • File permissions are set to 600 on Windows via os.chmod (restricted to owner).
    • Used by support teams to reproduce issues without needing the full system.
    • Quirks: If the log file is locked by another process, the dump may contain incomplete log data.
    • Potential issues: Large dump size on systems with many loaded modules; may exceed 5 MB.
    • Mitigation: Truncate module list to top 100 entries.
    • Performance: Dump generation typically <200 ms.< /li>
    • Security: Dump file is written to the user’s profile directory; ensure it is not shared inadvertently.
    • Future improvement: Add optional encryption flag.
    • Unit tests cover path overrides, redaction, and error handling.

Purpose: Performs an in‑place replacement of the Mantella DLL with a patched version while preserving the original for rollback.

  • Updates omni_settings.json['dll_patched'] flag.
  • Provides --restore option to revert to the backup.
  • Handles file locks by attempting to rename with MoveFileEx and MOVEFILE_REPLACE_EXISTING.
  • Logs each step, including hash verification before and after swap.
  • Important notes:
    • Requires the process that loaded the DLL to be terminated; prompts the user to close the game.
    • Quirks: On Windows Defender real‑time protection, the rename may be delayed; retries with exponential backoff.
    • Potential issues: If the backup cannot be created, the operation aborts to avoid corruption.
    • Performance: Swap operation ~300 ms on SSD.
    • Security: Only operates on files within the known game directory.
    • Future improvement: Add digital signature verification of the patched DLL.
    • Unit tests simulate file system using pyfakefs.

Purpose: Provides a utility class to locate and safely patch game INI configuration files for supported games (Skyrim, Fallout 4).

  • Imports os and logging for filesystem access and structured logging.
  • Class INISurgeon encapsulates the functionality.
  • Constructor __init__(self, logger, target_game="Skyrim") stores a logger, the target game name, and calls setup_targets() to build a list of INI file paths.
  • Method setup_targets(self) determines the user profile directory via os.environ['USERPROFILE'] and constructs absolute paths for the three primary INI files of the selected game.
  • Supports Fallout 4 and Skyrim Special Edition with distinct path patterns; logs an info message indicating which configuration is selected.
  • If an unknown game is supplied, logs a warning and returns an empty list, preventing accidental file modifications.
  • Method patch_files(self) iterates over self.target_files and attempts to open each file in read‑write mode to verify access.
  • Non‑existent files are silently skipped, ensuring the operation is idempotent and safe on fresh installations.
  • Permission errors are caught and logged as warnings, allowing the process to continue with remaining files.
  • Any other exception is logged as an error with the exception details for troubleshooting.
  • Successful access increments patched_count, which is reported at the end of the operation.
  • All logging uses the injected logger instance, enabling integration with the application's central logging system.
  • Design deliberately avoids making actual modifications; it serves as a scaffold for future INI sanitisation logic.
  • Quirks: On Windows systems with restrictive folder permissions, the script may lack write access to Documents\My Games without elevation.
  • Potential issues: Hard‑coded path separators assume Windows; cross‑platform usage would require os.path.join adjustments.
  • Performance: Scanning three files takes <1 ms on typical SSDs; the overhead is negligible.
  • Security: No external data is read or written beyond the user's own configuration files.
  • Future improvement: Implement actual INI parsing (e.g., using configparser) to apply safe defaults and validate values.
  • Future improvement: Add a dry‑run mode that reports which files would be patched without opening them.
  • Future improvement: Support additional games via a configurable mapping table.
  • Future improvement: Integrate with utils.safe_injector for atomic writes when modifications are applied.
